Unsupported or incomplete: guaranteed forced-clamshell behavior, powered-off charging guarantees, desktop widgets and macOS versions older than 13. Unknown hardware profiles are refused rather than guessed.

The installed development helper was validated only through read-only capabilities. Hardware control and scheduled system actions remain disabled on the validation machine. No physical effects are claimed from capability detection or fake-backend tests.


Version 0.3.38 fixes fresh ordinary-session startup when the selected policy requires system/lid sleep protection. It establishes inhibition before protection and enters the requested action only after protection succeeds; subsequent healthy policy rounds reuse the session. This applies to the updated app with the existing sleep-capable helper protocol. An independently restarted helper can still reject a previously cached app session; that failure requires recovery and re-enabling control. No hardware or sleep effects have been physically verified by this increment.


Version 0.3.38 includes a matching-app/helper multi-display Discharging sleep-entry path. It combines phase/display metadata atomically with discharge, rechecks root lid/adapter state and snapshot age, and separately attempts allowance, selected sleep protection and local user activity. Failure recovery and wake cleanup are implemented. Display topology is a bounded app snapshot; physical multi-display behavior, exact asynchronous ordering and the wider hardware/profile matrix remain unverified. The matching helper is included in the 0.3.38 packages; the installed validation helper has not been updated.


Version 0.3.38 ordinary sleep preparation honors pause-on-sleep directly: opt-out releases only sleep protection; opt-in attempts inhibition before release and preserves pending recovery on failure. It does not infer opt-in from a forced-discharge action. The complete change requires matching updated helper source; the validation machine’s installed helper remains unchanged. Software request ordering does not establish physical sleeping charge behavior.

Shared-module compatibility work: application/policy/hardware lookup calls retain the existing keys through older Foundation APIs, and IOKit default-port selection uses the system-appropriate SDK name. A dedicated compile gate targets macOS 11 on both architectures, including the streaming update transport, menu presentation and guarded automation declarations. A linked provider fixture checks weak App Intents loading and runs injected read-only providers on the current system. This does not establish full application or daemon operation on macOS 11/12; the packaged app minimum remains macOS 13.

Date display and effective Low Power Mode observation now use version-gated APIs with explicit legacy formatting and unknown-state handling. The menu icon has a legacy alpha-mask tint path. These changes retain the packaged macOS 13 requirement; complete macOS 11-target compilation and presentation fallbacks do not establish older-system runtime or native privileged installation.

Hardware-service inspection now separates its application status/preflight from the macOS 13 SMAppService backend. The macOS 11/12 source backend implements signed, authorized installation and job unregistration. Version 0.3.43 adds owned installed-file removal and an explicit modern-route handoff as described below. Actual old-system runtime acceptance remains unfinished; the packaged minimum stays macOS 13.

Login-startup development source now separates the macOS 13 native backend from an owned per-user LaunchAgent fallback for earlier systems, with fake-backend and temporary-directory tests. Actual logout/login, launchd overrides, native registration and old-system runtime have not been exercised. See [login startup](LOGIN-STARTUP.md).

Version 0.3.38 includes read-only installed-service classification, portable runtime preparation and an embedded older-helper metadata candidate. These are not a pre-13 authorization or removal backend. The development package remains ad-hoc signed and unnotarized; no administrator installation was exercised. Its fallback history view supplies native reading nodes and macOS 12 chart descriptors, but hosted assistive-technology reachability and actual audio playback remain unverified. Interface resources are intentionally limited to Simplified Chinese and English.


Version 0.3.42 implements the macOS 11/12 native registration backend with Authorization Services and SMJobBless, plus SMJobRemove for explicit job unregistration. Matching Apple-issued app/helper signatures, reciprocal ownership metadata and known installed-file ownership are required. Blocking authorization/removal run outside the main thread and overlapping operations are refused. Unregistration stops the job but retains installed files; version 0.3.43 supplies the separate full-removal and modern-route handoff action. The current ad-hoc packages cannot use this route. Physical macOS 11/12 execution, administrator interaction and a production signing/notarization pipeline remain unverified; the packaged minimum remains macOS 13.


Version 0.3.43 adds a full native legacy-removal path separate from job unregistration. A compatible blessed helper checks the requesting app's kernel audit token and matching Apple-issued signing team, verifies an already-granted administrator right without prompting in the root process, restores owned state and rejects any remaining charge/firmware/LED/sleep recovery record path. Descriptor-relative removal is restricted to its fixed root-owned installed binary and launchd plist. Partial file deletion and failed job removal retain retry progress within the current app/helper processes. A confirmed file-removal acknowledgement can finish a failed job-stop retry after the daemon has exited. Actual signed operation and crash/relaunch recovery are unverified; process-local retry state does not constitute a durable transaction. On macOS 13+, successful removal selects the modern registration route but does not automatically register it. Development-script installations still use their manual uninstall route.

The development uninstall script now checks that its launchd job and helper processes have exited before deleting installed files. It fails closed on unrecognized service or process state and preserves recovery records. Its negative paths have isolated tests; real root uninstall and older macOS launchctl behavior have not been validated.

Version 0.3.45 restricts the development uninstaller to the exact installer-generated launchd plist and rechecks that configuration before requesting a recovery restart. Modified or native-service configurations are retained for manual review. Failed restarts are reported explicitly. These checks do not establish atomicity against concurrent root actions.

Version 0.3.46 stages and verifies development-service upgrades, requires stopped service/processes and no pending recovery before replacing files, and attempts guarded rollback on replacement/bootstrap failure. Unsafe or native-service paths are refused; uncertain rollback preserves backup files. This is isolated filesystem/service-fixture evidence, not real root installation or durable crash-recovery validation. Native 0.3.45 English pages and read-only Shortcuts workflows were observed on the validation host; full localized discovery and numeric outputs remain unverified.

The production app remains unconfigured for signed updates by default. Default SDK scheduler installation on ordinary quit and cancellation/retry passed in the same disposable identities without using an immediate-install handler. The shared SDK session/KVO and production update-model projection have real informational-cycle coverage. Guarded product bootstrap/resume, actual service cleanup/update, deployment signing/notarization, older-system runtime and publication acceptance remain open; fixture success does not establish complete update parity.
