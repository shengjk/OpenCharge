This is a development release. Implemented policy, OS integration and physical hardware validation are separate milestones.

Unsupported or incomplete: guaranteed forced-clamshell behavior, powered-off charging guarantees and desktop WidgetKit extensions. Packages target macOS 11; runtime behavior on macOS 11/12 remains unverified. Unknown hardware profiles are refused rather than guessed.

The reviewed 0.3.54 development helper is installed on MacBookPro17,1. After an initially inconclusive bounded test, a separately authorized follow-up observed allow/inhibit/allow in driver snapshots newer than the first acknowledgement of each phase: positive current, zero current, then positive current. The helper was renewed within its lease, restoration was acknowledged and the previous controller was reopened. This proves basic gating on this one host, not app policy-limit cutoff, forced discharge, calibration, sleep/boot recovery, other helper binaries or other models. The app control opt-in and scheduled system actions remain disabled. Capability detection and fake-backend tests do not establish physical effects.


Version 0.3.38 fixes fresh ordinary-session startup when the selected policy requires system/lid sleep protection. It establishes inhibition before protection and enters the requested action only after protection succeeds; subsequent healthy policy rounds reuse the session. This applies to the updated app with the existing sleep-capable helper protocol. An independently restarted helper can still reject a previously cached app session; that failure requires recovery and re-enabling control. No hardware or sleep effects have been physically verified by this increment.


Version 0.3.38 includes a matching-app/helper multi-display Discharging sleep-entry path. It combines phase/display metadata atomically with discharge, rechecks root lid/adapter state and snapshot age, and separately attempts allowance, selected sleep protection and local user activity. Failure recovery and wake cleanup are implemented. Display topology is a bounded app snapshot; physical multi-display behavior, exact asynchronous ordering and the wider hardware/profile matrix remain unverified. The matching helper is included in the 0.3.38 packages; the installed validation helper has not been updated.


Version 0.3.38 ordinary sleep preparation honors pause-on-sleep directly: opt-out releases only sleep protection; opt-in attempts inhibition before release and preserves pending recovery on failure. It does not infer opt-in from a forced-discharge action. The complete change requires matching updated helper source; the validation machine’s installed helper remains unchanged. Software request ordering does not establish physical sleeping charge behavior.

A dedicated compile gate targets macOS 11 on both architectures, including the streaming update transport, menu presentation and guarded automation declarations. A linked provider fixture checks weak App Intents loading and runs injected read-only providers on the current system. This does not establish full application or daemon operation on macOS 11/12; the packaged app minimum remains macOS 13.

Date display and effective Low Power Mode observation now use version-gated APIs with explicit legacy formatting and unknown-state handling. The menu icon has a legacy alpha-mask tint path. Version 0.3.38 includes read-only installed-service classification, portable runtime preparation and an embedded older-helper metadata candidate. These are not a pre-13 authorization or removal backend. The development package remains ad-hoc signed and unnotarized; no administrator installation was exercised. Version 0.3.42 implements the macOS 11/12 native registration backend with Authorization Services and SMJobBless, plus SMJobRemove for explicit job unregistration. Matching Apple-issued app/helper signatures, reciprocal ownership metadata and known installed-file ownership are required. Blocking authorization/removal run outside the main thread and overlapping operations are refused. Unregistration stops the job but retains installed files; version 0.3.43 supplies the separate full-removal and modern-route handoff action. The current ad-hoc packages cannot use this route. Physical macOS 11/12 execution, administrator interaction and a production signing/notarization pipeline remain unverified; the packaged minimum remains macOS 13.


Version 0.3.43 adds a full native legacy-removal path separate from job unregistration. A compatible blessed helper checks the requesting app's kernel audit token and matching Apple-issued signing team, verifies an already-granted administrator right without prompting in the root process, restores owned state and rejects any remaining charge/firmware/LED/sleep recovery record path. Descriptor-relative removal is restricted to its fixed root-owned installed binary and launchd plist. Partial file deletion and failed job removal retain retry progress within the current app/helper processes. A confirmed file-removal acknowledgement can finish a failed job-stop retry after the daemon has exited. Actual signed operation and crash/relaunch recovery are unverified; process-local retry state does not constitute a durable transaction. On macOS 13+, successful removal selects the modern registration route but does not automatically register it. Development-script installations still use their manual uninstall route.

The development uninstall script now checks that its launchd job and helper processes have exited before deleting installed files. It fails closed on unrecognized service or process state and preserves recovery records. Its negative paths have isolated tests; real root uninstall and older macOS launchctl behavior have not been validated.

Version 0.3.45 restricts the development uninstaller to the exact installer-generated launchd plist and rechecks that configuration before requesting a recovery restart. Modified or native-service configurations are retained for manual review. Failed restarts are reported explicitly. These checks do not establish atomicity against concurrent root actions.

Version 0.3.46 stages and verifies development-service upgrades, requires stopped service/processes and no pending recovery before replacing files, and attempts guarded rollback on replacement/bootstrap failure. Unsafe or native-service paths are refused; uncertain rollback preserves backup files. This is isolated filesystem/service-fixture evidence, not real root installation or durable crash-recovery validation. Native 0.3.45 English pages and read-only Shortcuts workflows were observed on the validation host; full localized discovery and numeric outputs remain unverified.

Version 0.3.48 ordinary-exit cancellation restores retained inhibition and keeps failed/ambiguous restoration retryable after control is disabled. Version 0.3.49 persists ordinary Cancel Quit recovery intent and retries it on startup with control disabled. Completion requires both helper acknowledgement and saved clearance. Direct charge and LED grants must complete pending recovery first; portable backups omit this obligation. Injected service/storage failures cover retention and retry. This is cooperative configuration state, not a cross-client ownership protocol: failed intent persistence, older clients, forced termination and real hardware remain validation limits. Numeric exit transaction rollback is still unfinished.

Unreleased helper source provides a prepared numeric exit protocol: retained recovery responsibility until a matching commit, cancellation through the captured-value restore path, bounded transaction identities and stale/new-session rejection. The application now stages before waiting and commits only at its final exit decision. It retries a lost final reply with the same identity and offers explicit unconfirmed exit; cancellation after commit delivery cannot claim rollback. Matching-helper installation, actual transport, physical effects and crash/receipt recovery remain validation boundaries. Published 0.3.49 packages are unchanged.
