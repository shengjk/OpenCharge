# 整理决策与原因

1. 参考 [Droidline](https://github.com/KnifeLemon/Droidline/tree/main) 的仓库组织方式：根目录保留中英文 README、贡献指南、安全说明、许可证和更新记录，详细使用、架构和状态说明进入 docs。新贡献者可以先看用途，再找到构建与验证入口。
2. 保留 SwiftPM 标准 Sources / Tests 和现有 Scripts 目录。不同平台的模块布局不宜直接照搬；保持现有路径能避免无意义的构建、安装和文档路径变动。
3. 将应用大文件拆成模型、生命周期、导航、公共组件和各页面，保留同一 SwiftPM target。减少单文件耦合，同时避免引入无必要的包依赖。
4. 将开发调查记录、版本对照和本机路径移出公开项目，重写为 OpenCharge 自身的功能、架构与限制说明。应用中的品牌专属检测和提示一并移除；保留通用的单控制器提示以及硬件能力检查、所有权恢复。
5. 使用已交付稳定功能作为整理基线，未接入应用的温度探针实验保存在项目外，避免把未完成开发混入首次公开提交。
6. 保留第三方 MIT 声明和公开硬件协议来源。清理产品内容不改变必要的开源署名。
7. 增加统一验证入口和 GitHub 协作模板，构建产物、缓存、历史、诊断和本机配置均排除出仓库。CI 不安装服务、不更改电池或系统电源状态。
8. 功能状态区分策略通过、只读连接与实机效果；不将通用二进制、模拟测试或能力读取写成物理控制已验收。
9. 本地开发与远程发布分开执行。只有用户明确授权时才提交或推送。


## 0.3.3：温度与容量来源

使用一个只读遥测入口供界面、CLI 和快捷指令共享，避免相同字段在不同入口代表不同传感器。优先使用固定电池传感器，失败时保留明确标注的系统后备值；系统温度和虚拟温度分别留存，不混成一个读数。满充容量优先采用有效原始容量，系统标称容量单独展示，避免把两个定义不同的数值当作同一个健康比例。macOS 状况与维护建议也分别记录。旧历史没有来源信息时保持未知，不反推历史。


## 0.3.4：原生拖动与整行落点

实测发现编辑行的拖动没有改变顺序，因此将拖动手柄与整行落点接到原生 AppKit 事件。保留 SwiftUI 控件和可访问的上下按钮，避免复选框手势干扰拖动。只有同一弹窗布局中的已知组件可以被接受；在真正放下时才改顺序，无效落点不保存半途变化。底部改为“完成编辑”，明确设置即时保存，不将离开编辑模式误称为撤销。预览交互验收与真实菜单栏图标生命周期验收分别记录。


## 0.3.5：真实状态栏与独立更新状态

直接持有原生状态栏图标和锚定弹窗，并让 Command-3 触发真实按钮，便于键盘使用和实际生命周期验证。预览与真实弹窗分别维护状态，避免关闭一个窗口误停另一个。沿用系统设置窗口与现有模型，不引入第三方依赖；设置中显示能耗读取是否暂停。将自动化验证与人工验证分开记录：打开、关闭与暂停由界面检查确认，真实弹窗排序由用户手动确认，不把预览成功直接当作真实弹窗成功。


## 0.3.6：直接编辑与动画偏好

提供设置按钮与 Command-4，直接打开真实菜单栏编辑器，减少调整布局时的操作。预览和真实弹窗各自维护临时编辑状态，关闭时仅清除对应状态；布局仍即时保存，避免测试预览影响真实弹窗。动画偏好单独保存，同时让系统“减少动态效果”具有更高优先级，保持可访问性。


## 0.3.7：同次开机的充电恢复日志

把充电修改前的状态先同步落盘，再允许写硬件，避免服务崩溃后只剩固件状态、无法判断本服务曾修改什么。日志限制固定键和字节，保存在 root 私有目录，并检查权限、链接和独占锁；不能从 IPC 指定路径或内容。恢复仅限同次开机，跨开机不重放旧记录，避免覆盖固件启动后的新状态。恢复原值失败时保留记录重试；磁盘写入失败时不继续写硬件。保留停充只在服务存活时有效，崩溃重启优先释放旧会话。以假寄存器和实际退出子进程验证中断边界，没有更新已安装服务或进行物理充放电。


## 0.3.8：独立灯光恢复与闪烁写盘成本

灯光和充电使用不同记录，避免一种状态的恢复清除另一种状态；共用私有目录和锁，不新增由客户端指定路径的能力。服务重启先恢复捕获值，不自动继续旧闪烁模式。只在引入新状态时同步落盘；如果已有记录覆盖闪烁两态，就复用记录，避免每秒同步磁盘。外部改动继续保留，写入或恢复失败进入清理重试。以假 ACLC、真实退出的子进程和共享文件隔离验证这些边界，不能替代真实适配器测试。


## 0.3.9：菜单栏图标与低电量染色

使用独立绘制的电池外形和系统符号，提供状态、电池单色、电池彩色与 OpenCharge 图标，不引入其他产品的图形资源。电量填充跟随实际 macOS 百分比，未知读数保持未知，不用策略上限假装实际电量。接电放电需同时有物理接入与有效负电流，避免把普通电池供电误标成主动放电。低电量染色默认关闭，只读取系统实际模式并监听通知，不修改电源设置；仅图标染色，文字保留系统颜色。仅图标模式只隐藏文字，不再顺带改变所选样式。


## 0.3.10：以原生性能验收补足图标测试

0.3.9 的图形与逻辑测试通过，但实际运行暴露状态栏快照触发外观观察、再更新图标的回环，静态设置窗口也持续占用 CPU。将其 Release 转回草稿并保留标签与记录，不覆盖已推送版本。改为观察应用级外观，并在分配图像前保存语义呈现键；内容不变时不重绘，策略提示独立更新。新增 1000 次重复事件回归测试，同时用实际应用 CPU 时间差复测，避免把合成渲染通过当作运行成本已验收。

同一静态设置场景的实际 CPU 时间差复测：修复前约 65.7% 单核，修复后两次约 2.39% 与 0%，选择彩色图标后约 1.8%。这些是本机短样本，不作为所有设备或场景的性能承诺；实际低电量模式切换和更多显示环境仍需验收。


## 0.3.11：先建立透明的检查与校验下载链路

从固定公开仓库读取发布信息，以 SemVer 比较版本，同时检查 GitHub 的预览标记，避免把发布时间、列表顺序或撤回的草稿当成最新版本。Apple Silicon 优先原生包，Intel 选择通用包；缺少最新版本的完整资产时明确提示，不偷偷回退到旧版。

自动检查默认关闭，开启后每 12 小时检查；下载必须点击。请求不携带电池读数、本机标识或凭据，设置与应用菜单使用同一状态对象，避免重复请求。流式下载限制大小和重定向主机，校验大小、发布校验和及可用的 API 摘要，最后用系统 API 设置并读回隔离属性。失败清理本次目录，成功只在访达中显示，不运行下载文件。

当前没有独立发布签名和公证链，因此保留手动替换应用，后台服务也不随下载替换。校验和证明下载与同一发布者提供的记录一致，不能代替独立签名。这是更新分发的一个可验证阶段，完整自动安装仍在状态清单中待完成。除确定性测试外，增加匿名公开网络测试，并在发布前保留真实界面与 CPU 时间差验收。


## 0.3.12：主动放电结束后再完成退出

不再只发送恢复请求就结束进程。退出先暂停策略刷新和新的应用内控制操作，保留用户选择的恢复充电或退出后保持停充策略；此前由本应用确认执行过主动放电时，随后观察系统供电来源。连续稳定至少半秒的外部供电，或明确物理断电且系统使用电池，才允许自动结束；未知值不能当作拔线成功。

用 AppKit 的延迟退出回复机制承载该过程，并将计时器加入 modal-panel 运行模式，避免退出等待期间计时器停转。15 秒未确认或恢复请求失败时停在选择窗口，不自动强制结束。取消退出关闭真实充电控制并保持应用运行；校准需要明确继续，防止取消退出意外重新启动放电。重试和仍然退出分别是明确动作，关闭窗口也按取消处理。真实放电与显示切换仍没有实机证据，使用独立的假服务原生程序验证运行循环与交互，不为演示开启硬件。
